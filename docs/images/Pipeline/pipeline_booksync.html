1Vue d'ensemble du Pipeline

Le pipeline CI/CD BookSync automatise l'ensemble du processus de test, build et déploiement. À chaque push sur main, le pipeline exécute les tests, construit l'image Docker et la déploie sur Azure Container Apps avec un système de rollback automatique en cas d'échec.

Push sur main

JOB 1: Tests
→
JOB 2: Build
→
Deploy
→
Health Check

Résultats Possibles

✓ Succès

Health check réussi (HTTP 200)

→ Déploiement Terminé

✗ Échec

Health check échoué

→ Rollback Automatique

Activation du Rollback Automatique

3Workflow de Rollback Manuel

Le workflow de rollback peut être déclenché manuellement via GitHub Actions. Il permet de revenir à une version précédente en cas de problème en production.

Déclenchement du Rollback

Options disponibles:

  • previous - Retour à la version immédiatement précédente
  • specific - Retour à un tag/SHA spécifique
  • latest_stable - Retour à la dernière version stable

Processus du Rollback

📋 JOB 1: Préparation

  • Connexion Azure
  • Récupération image actuelle
  • Détermination image cible

⚙️ JOB 2: Exécution

  • Sauvegarde état actuel
  • Upload artefact (backup)
  • Update Container App

🏥 JOB 3: Vérification

  • Health check: /predict/health
  • 10 tentatives max
  • Intervalle: 15s

JOB 4: Notification

📧 Notification du résultat

Envoi du statut (succès/échec) - Extensible vers:

  • Slack
  • Microsoft Teams
  • Email

7Commandes de Rollback

Via Makefile

Commandes locales pour gérer le rollback:

make rollback-list

📋 Lister les images disponibles

make rollback-current

👀 Voir l'image actuellement déployée

make rollback-previous

⏮️ Rollback vers la version précédente

make rollback-to TAG=<sha_du_commit>

🎯 Rollback vers une version spécifique

make health-check

🏥 Vérifier la santé de l'application

Via GitHub Actions

  1. Aller dans l'onglet Actions du repository
  2. Sélectionner le workflow Rollback Deployment
  3. Cliquer sur Run workflow
  4. Choisir le type de rollback
  5. Exécuter et surveiller les logs
